# B站评论防和谐(biliAntiShadowban)

## 作者：[@依然匹萨吧](https://space.bilibili.com/6297797)

## 功能介绍
**[介绍视频](https://www.bilibili.com/video/BV1MRhf6bEYw)**

**B站评论防和谐**是一个屏蔽检测浏览器插件，在 B 站评论输入框的发送按钮旁加一个「敏感检测」按钮：发布前一键自查**敏感词、不友善表达、图片风险**，给出**精确到第几个字**的修改建议；并为你**自己已发过的评论**(包含文字、图片)标注**他人是否可见**。

> 非官方第三方工具，与哔哩哔哩无任何隶属关系。检测结果为本地启发式推断，**不代表平台官方审核结论**。使用前请阅读 [法律声明](LEGAL.md) 与 [隐私政策](PRIVACY.md)。

### 1. 官方判定核验

零写入
**B站不存在任何可读取审核规则的公开接口**，阿瓦隆词库保密、且随评论区/账号等级/隐藏分动态变化。所以「发送前预判」在技术上**不可能**是官方结果。真正的官方判定只在你自己发送之后才存在。

本扩展**不代你发送、也不制造任何测试评论**，只做两件纯读取的事：

1. **旁路读取官方响应** —— 你点击B站自己的发送按钮后，读取该请求的官方返回码与评论 ID。**评论数量增量为 0。**
2. **只读比对可见性** —— 数秒后用公开只读接口比对登录态与游客态，判断是否被 ShadowBan 或已被删除。

结果以浮层形式在发送后自动弹出：

| 官方信号 | 含义 | 可信度 |
|---|---|---|
| `code=12016` | 发送阶段被官方直接拒绝，命中顶级词库 | **全站通用，最高** |
| `code=12015/12051/12035` | 需验证码 / 查重 / 被UP主拉黑 | 高 |
| ShadowBan | 登录可见、游客不可见 | 客观事实 |
| 系统秒删 | 发出后评论消失 | 客观事实 |

> **局限**：判定只能在**发送之后**取得。审核存在「秋后算账」——初始正常、一段时间后才被隐藏，即时结果无法预测，建议稍后用评论旁的徽标复查。
>
> 实现方式：页面世界包装 `fetch`/`XHR`，**仅对评论端点**旁路读取响应，其余请求原样放行。不读取 csrf、不读取任何 Cookie，因此**不需要 `cookies` 权限**。

### 2. 发布前敏感检测
纯本地，明确标注为推测
- 覆盖**视频页、动态/图文页、专栏页**的评论输入框（含新版 `<bili-comments>` Web Component 与旧版评论区）。
- 检测维度：人身攻击/辱骂、不友善、地域群体攻击、低俗、导流广告、隐私信息（手机号/身份证/QQ）、刷屏。
- **精确定位**：结果面板直接高亮原文中的问题字符，并标注「第 N 个字符 →『xxx』」。
- **抗绕过归一化**：全角半角、繁简、大小写、同形字（`0→o`）、零宽字符、空格/符号拆字、重复字符拉伸，均可还原后匹配，且能映射回原文的真实位置。
- 一键生成**建议文案**（高危删除、中危打码），可直接替换回输入框。
- 图片检测：肤色占比、二维码栅格特征、文字密度，**图片不离开你的设备**。

面板上「本地推测 · 非官方结果」与「官方真实检测」**分区标注、配色不同**，绝不混淆。

### 3. 和谐处理
有风险，默认需确认后启用
把命中的文字改写以降低被自动规则识别的概率，三种方式：

| 方式 | 效果 | 说明 |
|---|---|---|
| **同音字** | `你好` → `泥豪` | 从离线同音字表取候选，「换一批」可切换不同写法 |
| **零宽字符** | `你好` → `你‍好` | 字符间插入 U+200B/200C/200D/2060/FEFF，**视觉完全一致**，预览中以 `␣` 标出 |
| **混合** | 优先同音字，无候选的字用零宽隔开 | — |

手机号/身份证等隐私类命中会**强制走零宽**（同音替换号码没有意义）。同音字表由 `tools/gen_homophones.py` 借助 pypinyin 离线生成为 `rules/homophones.json`，**运行时无任何依赖**。

> **务必理解**：该功能本质是规避内容审核。它**不会让违规内容变得合规** —— 平台仍可通过语义模型和人工审核判定违规，而且**「刻意规避审核」本身在多数平台规则下即构成违规，可能导致比原内容更重的处罚**。仅建议用于你确信属正常表达却被自动规则误判的情况。默认需在设置页勾选确认风险后才会出现在面板中。

### 4. 已发评论可见性标识
在你自己的评论后显示徽标：

| 徽标 | 含义 |
|---|---|
| ✓ 他人可见 | 游客视角下也能看到 |
| ⚠ 仅自己可见 | 登录能看到、游客看不到 —— 很可能已被拦截 |
| ◐ 已折叠 | 需展开才可见 |
| ? 无法确定 | 分页较深或接口受限，不做臆测 |

原理：对比**登录视角**与**游客视角**（`credentials: 'omit'`）的公开评论列表差异。

## 面向大规模分发的设计

| 关注点 | 做法 |
|---|---|
| **用户间互不冲突** | 无任何服务端，无共享状态。每个安装实例只用**本机浏览器自己的登录会话**，不共享 Cookie、不做账号轮换、不使用代理池 |
| **同一用户多标签页不放大请求** | 所有网络请求集中在后台 Service Worker 的**全局唯一队列**，内容脚本不直接发请求 |
| **防限流** | 全局串行 + 令牌桶（约 5s/次，突发上限 5）+ 最小间隔 1.8s + 随机抖动 ≤1.2s + 指数退避重试 |
| **反爬friendly** | 识别 412/429/-509/-799 风控响应；连续 3 次风控**自动熔断 10 分钟**；相同请求合并；结果缓存 10 分钟 |
| **完全只读不写** | 扩展不发送、不删除、不重放任何评论，评论数量增量为 0；不请求 `cookies` 权限 |
| **样式隔离** | 全部类名 `bsc-` 前缀 + `data-bsc` 标记，shadow DOM 内按需注入样式，不修改 B 站原有节点结构 |

## 安装

### 从源码构建
```bash
npm install
node build.mjs          # 产出 dist/chrome 与 dist/firefox
npm run pack            # 另外产出 dist/*.zip
```

### 从zip直接安装

#### Chrome / Edge
1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 开启「开发者模式」和「允许来自其他应用商店的扩展」
3. 解压对应版本zip
4. 「加载已解压的扩展程序」→ 选择解压后的文件夹

#### Firefox
1. 打开 `about:debugging#/runtime/this-firefox`
2. 「临时载入附加组件」→ 选择 `dist/firefox/manifest.json`
3. 永久安装需经 AMO 签名（`web-ext sign`）

装好后登录 B 站，打开任意视频/动态/专栏页即可。

## 项目结构

```
src/
  core/
    normalize.js    归一化 + 原文位置映射（抗绕过的关键）
    ac.js           Aho-Corasick 多模式匹配，词表扩到数千条也不卡
    detector.js     规则引擎，输出精确到字的 Finding[]
    image.js        本地图片启发式分析（肤色/二维码/文字密度）
    harmonize.js    和谐处理：同音字替换 / 零宽字符插入 / 混合
    intercept.js    页面世界拦截器：旁路读取官方发评响应（不发起任何请求）
  content/
    dom.js          B站评论区 DOM 适配（新旧版 + shadow DOM 穿透）
    main.js         按钮注入、结果面板、可见性徽标
    panel.css       全部 bsc- 前缀，含暗色模式
  bg/
    service-worker.js  后台消息路由，唯一的网络出口
    limiter.js         令牌桶 + 串行队列 + 退避 + 熔断
    wbi.js             WBI 签名（含纯 JS MD5）
    visibility.js      登录/游客双视角比对
    official.js        官方判定：返回码解析 + 只读可见性核验（零写入）
  ui/popup, ui/options  弹窗与设置页（设置页内含完整法律声明）
rules/rules.json       启发式词库与正则规则，可自行扩充
rules/homophones.json  离线生成的同音字候选表（331 字）
tools/gen_homophones.py 同音字表生成脚本（开发时用）
```

## 自定义词库
编辑 `rules/rules.json` 的 `keywords` / `regex` / `softPatterns` 后重新构建。用户侧也可在设置页配置**白名单**，避免昵称、专有名词误报。

node test.mjs           # 检测精度与区间准确性（11 项）

## 已知限制
- 词库是**示例性启发式规则**，不是平台真实审核表，存在误报漏报。
- 可见性检测默认只查前 2 页评论，更深分页会返回「无法确定」。
- B 站接口/DOM 结构可能随时变更导致功能失效。
- 和谐处理**不保证**能绕过平台审核，且规避行为本身有被处罚的风险。
- 官方判定只能在发送后取得，且无法预测「秋后算账」式的延迟隐藏。
